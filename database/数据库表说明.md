# WMS 数据库表说明

> 供应链智能仓储管理系统 (WMS) · Oracle 19c  
> 配套文件：`schema/WMS.pdm`（ER 图）、`schema/tables.sql`（建表脚本）

---

## 一、整体结构

共 **11 张表**，分为 4 个业务域：

```
用户与权限          商品与分类          供应链              订单与审计
──────────          ──────────          ──────              ──────────
users               categories          suppliers           orders
                    products            product_suppliers   order_details
                    inventory                               inbound_orders
                                                            inbound_order_lines
                                                            audit_logs
```

**两个容易混淆的订单表：**

| 表名 | 用途 | 关联对象 |
|------|------|----------|
| `orders` | **销售订单**（客户下单、出库） | 关联 `users`（客户） |
| `inbound_orders` | **采购入库单**（向供应商进货） | 关联 `suppliers`（供应商） |

**商品与库存分离：**

| 表名 | 用途 |
|------|------|
| `products` | 商品基本信息（名称、分类、售价） |
| `inventory` | 库存数量（与 `products` 一对一） |

---

## 二、表关系概览

```
users ─────┬──→ orders ──→ order_details ──→ products
           │                                      ↑
           ├──→ inbound_orders (created_by)       │
           │         ↓                            │
           └──→ audit_logs (changed_by)    categories
                     ↑                            ↓
              inventory ←────────────────── products
                     ↑                            ↓
              inbound_order_lines ←── inbound_orders ──→ suppliers
                                              ↑
                                    product_suppliers
```

## 三、各表详细说明

### 1. users — 用户表

**用途**：系统登录账号，含管理员、仓储操作员、客户。

| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | NUMBER(10) | 主键 |
| username | VARCHAR2(64) | 用户名，唯一 |
| password_hash | VARCHAR2(256) | 密码哈希（非明文） |
| phone | VARCHAR2(20) | 手机号，可空 |
| role | VARCHAR2(20) | 角色，见下表 |
| created_at | TIMESTAMP | 创建时间 |

**role 取值：**

| 值 | 含义 | 典型场景 |
|----|------|----------|
| ADMIN | 管理员 | 全部权限 |
| OPERATOR | 仓储操作员 | 入库、盘点、库存管理 |
| CUSTOMER | 客户 | 下单购买（关联 `orders`） |

**关联**：被 `orders`、`inbound_orders`、`audit_logs` 引用。

**相关开发**：白沁禾（Login / Register / 权限路由）

---

### 2. categories — 分类表

**用途**：商品分类，支持父子层级（如「电子产品 → 手机」）。

| 字段 | 类型 | 说明 |
|------|------|------|
| category_id | NUMBER(10) | 主键 |
| category_name | VARCHAR2(100) | 分类名称 |
| parent_category_id | NUMBER(10) | 父分类 ID，可空（顶级分类为空） |

**关联**：自关联（父分类）；被 `products` 引用。

---

### 3. products — 商品表（SKU 主数据）

**用途**：商品基本信息。**库存数量不在本表**，见 `inventory`。

| 字段 | 类型 | 说明 |
|------|------|------|
| product_id | NUMBER(10) | 主键 |
| product_name | VARCHAR2(200) | 商品名称 |
| category_id | NUMBER(10) | 所属分类 |
| unit_price | NUMBER(12,2) | 销售单价 |
| created_at | TIMESTAMP | 创建时间 |

**关联**：→ `categories`；← `inventory`、`order_details`、`product_suppliers`、`inbound_order_lines`。

**相关开发**：白沁禾（SkuManage 页面）

---

### 4. inventory — 库存表

**用途**：记录每个商品的当前库存，支持乐观锁防并发冲突。

| 字段 | 类型 | 说明 |
|------|------|------|
| inventory_id | NUMBER(10) | 主键 |
| product_id | NUMBER(10) | 商品 ID，唯一（一商品一条库存记录） |
| quantity | NUMBER(12,3) | 当前库存数量，≥ 0 |
| version | NUMBER(10) | 乐观锁版本号，每次变更 +1 |
| updated_at | TIMESTAMP | 最后更新时间 |

**关联**：→ `products`（一对一）。

**注意**：入库、出库、盘点都改这张表；`trg_stock_audit` 触发器会记录变更到 `audit_logs`。

**相关开发**：李佳恒（InventoryService / Dashboard）、李展鸿（入库存储过程）

---

### 5. suppliers — 供应商表

**用途**：供应商基本信息。

| 字段 | 类型 | 说明 |
|------|------|------|
| supplier_id | NUMBER(10) | 主键 |
| supplier_name | VARCHAR2(200) | 供应商名称 |
| contact_name | VARCHAR2(64) | 联系人 |
| contact_phone | VARCHAR2(20) | 联系电话 |

**关联**：← `product_suppliers`、`inbound_orders`。

**相关开发**：白沁禾（SupplierManage 页面）

---

### 6. product_suppliers — 商品-供应商关联表

**用途**：同一商品可由多个供应商供货，记录各供应商的供货价。

| 字段 | 类型 | 说明 |
|------|------|------|
| ps_id | NUMBER(10) | 主键 |
| product_id | NUMBER(10) | 商品 ID |
| supplier_id | NUMBER(10) | 供应商 ID |
| supply_price | NUMBER(12,2) | 该供应商的供货价 |

**约束**：`(product_id, supplier_id)` 唯一。

**关联**：→ `products`、`suppliers`（多对多中间表）。

---

### 7. orders — 销售订单表

**用途**：客户下单产生的**销售/出库**订单（不是采购入库）。

| 字段 | 类型 | 说明 |
|------|------|------|
| order_id | NUMBER(10) | 主键 |
| user_id | NUMBER(10) | 下单客户 |
| total_price | NUMBER(14,2) | 订单总价 |
| status | VARCHAR2(20) | 订单状态 |
| order_time | TIMESTAMP | 下单时间 |

**status 取值：**

| 值 | 含义 |
|----|------|
| PENDING | 待支付 |
| PAID | 已支付 |
| SHIPPED | 已发货 |
| COMPLETED | 已完成 |
| CANCELLED | 已取消 |

**关联**：→ `users`；← `order_details`。

---

### 8. order_details — 销售订单明细表

**用途**：一张销售订单包含哪些商品、各多少数量。

| 字段 | 类型 | 说明 |
|------|------|------|
| detail_id | NUMBER(10) | 主键 |
| order_id | NUMBER(10) | 所属销售订单 |
| product_id | NUMBER(10) | 商品 |
| quantity | NUMBER(12,3) | 购买数量 |
| unit_price | NUMBER(12,2) | 成交单价（下单时快照） |

**关联**：→ `orders`、`products`。

---

### 9. inbound_orders — 采购入库单

**用途**：向供应商采购、货物入库的单据（WMS 核心流程之一）。

| 字段 | 类型 | 说明 |
|------|------|------|
| inbound_id | NUMBER(10) | 主键 |
| supplier_id | NUMBER(10) | 供应商 |
| status | VARCHAR2(20) | 入库单状态 |
| created_by | NUMBER(10) | 创建人（操作员），可空 |
| created_at | TIMESTAMP | 创建时间 |
| received_at | TIMESTAMP | 到货/完成时间，可空 |
| remark | VARCHAR2(500) | 备注 |

**status 取值：**

| 值 | 含义 |
|----|------|
| DRAFT | 草稿 |
| SUBMITTED | 已提交 |
| PARTIAL | 部分到货 |
| RECEIVED | 全部到货 |
| CANCELLED | 已取消 |

**状态流转**：`DRAFT → SUBMITTED → PARTIAL / RECEIVED`

**关联**：→ `suppliers`、`users`；← `inbound_order_lines`。

**相关开发**：李展鸿（Inbound 页面 + `proc_inbound` 存储过程）

---

### 10. inbound_order_lines — 采购入库明细

**用途**：一张入库单里每种商品的订购量与实收量。

| 字段 | 类型 | 说明 |
|------|------|------|
| line_id | NUMBER(10) | 主键 |
| inbound_id | NUMBER(10) | 所属入库单 |
| product_id | NUMBER(10) | 商品 |
| quantity_ordered | NUMBER(12,3) | 订购数量 |
| quantity_received | NUMBER(12,3) | 已收数量，默认 0 |
| unit_price | NUMBER(12,2) | 采购单价，可空 |

**关联**：→ `inbound_orders`、`products`。

**入库逻辑**：确认收货时，`quantity_received` 增加，同时通过存储过程更新 `inventory.quantity`。

---

### 11. audit_logs — 审计日志表

**用途**：记录数据变更历史，尤其用于库存变动追溯。

| 字段 | 类型 | 说明 |
|------|------|------|
| log_id | NUMBER(19) | 主键 |
| table_name | VARCHAR2(64) | 被变更的表名 |
| record_id | NUMBER(19) | 被变更记录的 ID |
| action | VARCHAR2(10) | INSERT / UPDATE / DELETE |
| old_value | CLOB | 变更前内容（JSON 或文本） |
| new_value | CLOB | 变更后内容 |
| changed_by | NUMBER(10) | 操作人，可空 |
| changed_at | TIMESTAMP | 操作时间 |

**关联**：→ `users`（操作人）。

**写入方式**：由 `trg_stock_audit` 触发器在 `inventory` 变更时自动写入，应用层一般只读。

## 六、存储过程（入库模块）

文件：`procedures/proc_inbound.sql`

| 过程 | 用途 | 关键机制 |
|------|------|----------|
| `proc_inbound_create` | 创建采购入库单 + 明细行 | 解析 JSON 明细数组，批量插入 |
| `proc_inbound_submit` | 提交入库单（DRAFT → SUBMITTED） | 状态校验 |
| `proc_inbound_receive` | **原子化收货确认**（核心） | `SELECT FOR UPDATE` 行锁 + `version` 乐观锁 + 自动更新入库单状态 |
| `proc_inbound_cancel` | 取消入库单 | 自动回退已收库存，更新 inventory |

**proc_inbound_receive 调用签名：**
```sql
PROCEDURE proc_inbound_receive (
    p_line_id           IN  NUMBER,       -- 明细行 ID
    p_receive_quantity  IN  NUMBER,       -- 本次收货数量
    p_operator_id       IN  NUMBER,       -- 操作人 ID（可选）
    p_expected_version  IN  NUMBER,       -- 乐观锁版本号（可选，NULL 则跳过校验）
    o_received_total    OUT NUMBER,       -- 该行累计已收
    o_new_version       OUT NUMBER,       -- 更新后 inventory.version
    o_result            OUT NUMBER,       -- 0=成功，-100~-104=参数错误，-200=版本冲突
    o_message           OUT VARCHAR2      -- 结果消息
);
```

**原子性保证：**
- 使用 `PRAGMA AUTONOMOUS_TRANSACTION` 独立事务
- `SELECT ... FOR UPDATE` 锁 inventory 行 → 更新 inbound_order_lines → 更新 inventory → COMMIT
- 异常时 ROLLBACK，保证明细行与库存同步

## 七、触发器（库存审计）

文件：`triggers/trg_stock_audit.sql`

| 对象 | 说明 |
|------|------|
| `trg_stock_audit` | AFTER INSERT/UPDATE/DELETE ON inventory，FOR EACH ROW |
| `wms_ctx_pkg` | 应用上下文管理包，传递操作人 ID 给触发器 |

**审计内容：**
- `table_name`：固定为 `'INVENTORY'`
- `old_value` / `new_value`：JSON 格式快照 `{"inventory_id":...,"product_id":...,"quantity":...,"version":...,"updated_at":"..."}`
- `changed_by`：从 `SYS_CONTEXT('WMS_CTX', 'operator_id')` 读取

**应用层设置操作人：**
```sql
EXEC wms_ctx_pkg.set_operator(2);  -- 设置当前操作人
```
